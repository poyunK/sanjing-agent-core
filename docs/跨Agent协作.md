# 一个项目，多种 Agent：你只负责转交文件

这份技能叫 `local-agent-handoff`，协议版本为 LAH/1.0。它适用于 Codex、Claude Code、DeepSeek Harness，以及其他能读取同一本地项目的 Agent。两边的聊天记忆不共享；共同依据是源码、项目文档、任务书、结果和验收回执。

你不用写 JSON、操作 Git 来交接，或替一方解释另一方的技术结果。Agent 负责这些操作。你在 GUI 里说清意图，然后转交它生成的文件即可。

## 你日常说什么

| 你在任意 GUI 说 | Agent 应该做什么 | 你要转交什么 |
|---|---|---|
| “登记一项待办：……，暂时不执行。” | 整理目标与验收标准，写入共同看板 | 暂时不需要文件 |
| “把这个任务交给 Claude Code / DeepSeek Harness / 另一个 Agent。” | 根据当前源码生成 TASK.md，登记执行方并暂停自身写入 | TASK.md |
| “请按这份任务书执行。” | 读协议、核对版本、领取、完成并生成 RESULT.md | 把 RESULT.md 交回派单 GUI |
| “这是对方的结果，请验收。” | 核对关联和文件、复验、记录 RECEIPT.md 并更新看板 | 通常不用转交；返工时转交新的 TASK.md |
| “新会话了，恢复当前任务。” | 读取当前状态和必要文件，继续未完工作 | 不需要补讲之前的聊天 |

双方都可以派单，也都可以接单。接单的 GUI 名称只是标签，代码没有固定厂商列表，不需要对方的 API Key 或会话 ID。

## 任务看板放在哪里

当前工程的看板是 `.handoff-local/BOARD.html`，直接打开即可；文字版是 `.handoff-local/BOARD.md`，完整索引为 BOARD.json。

```text
待办 → 已派单 → 执行中 → 待验收 → 已验收
                              ├→ 需返工 → 新任务
                              └→ 未接受
任何未结束任务可以在停止执行并核对后取消
```

“执行方完成”与“派单方已验收”是两个不同状态。待验收的任务仍占用这份工作副本，派单方先检查，不能顺手开始改另一批代码。需要并行开发时，应另行安排独立工作副本与集成任务，而不是让两个 GUI 在这里同时写文件。

每项任务保留目标、负责人、优先级、前置依赖、阶段变化、任务文件和结果证据。关闭 GUI 不会丢失；新会话从磁盘恢复。待办可以改规格，旧版本保留；已派出的任务不能悄悄改变范围。任务过多时默认看板只显示最近三十项结束记录，完整历史一直保留。

看板是本地静态页面，Agent 每次操作后刷新文件，你刷新页面看最新内容。它没有联网协作服务，也没有自动向另一个 GUI 发消息。`.handoff-local/` 被 Git 忽略，任务中的个人背景不会自动上传到公开仓库。它保留于这份工作副本，不承诺电脑损坏后的备份；需要迁移时让 Agent 做经过脱敏的备份与重新派单。

## 其他 Agent 第一次怎么加载

仓库根的 AGENTS.md 是共同入口；CLAUDE.md 导入它，Claude 原生技能入口指向同一协议。规范目录只有一份：

```text
.agents/skills/local-agent-handoff/
├── SKILL.md
├── agents/openai.yaml
├── assets/                 规格与回执示例
├── references/             字段契约、按角色操作说明
└── scripts/handoff.py      标准库交接与看板工具
```

Codex 项目技能目录和 AGENTS.md 的加载方式见 [OpenAI 官方技能说明](https://developers.openai.com/codex/skills/) 与 [项目指令说明](https://developers.openai.com/codex/guides/agents-md/)。Claude Code 的项目技能和 CLAUDE.md 导入方式见 [Claude 官方技能说明](https://code.claude.com/docs/en/skills) 与 [项目记忆说明](https://code.claude.com/docs/en/memory)。不同客户端版本、项目设置和权限可能影响自动加载；这些入口已放到磁盘，不代表已经在每个 GUI 中验证过加载。

没有技能发现或 AGENTS.md 支持的 Harness，首次给它下面这一段即可。每份 TASK/RESULT 开头也自带具体入口；不用你重复讲项目背景：

> 先读取项目根的 AGENTS.md 和 .agents/skills/local-agent-handoff/SKILL.md，按 LAH/1.0 操作。新会话先检查任务看板和 ACTIVE.json。此 GUI 与其他 Agent 共享本地源码，请避免重复领取、同时写入和重复应用改动。收到任务文件后核对项目与版本，再执行。

这里默认“双方能读取同一个文件夹”。如果一方其实是云端聊天窗口、另一个 checkout 或另一台机器，要重新准备相应交接，不能用文件哈希代替缺失源码。

## 一次交接实际保存了什么

任务书就像订单：目标、必要背景、已确认决定、允许修改的文件、禁止扩展的范围、验收标准。脚本附上当时真实文件哈希和任务 ID；不是把所有聊天压成一份“记忆包”。

结果就像施工回报：实际改了哪些文件、运行过什么检查、哪些没有验证、还差什么。脚本从当前文件计算改动，不让模型猜哈希。接收方再核对真实文件是否仍与结果一致。

验收回执就像交付签收：派单方记录自己的检查和接受、返工或拒绝结论。**关联检查通过，只能证明任务和字节对上了；不能证明代码没有缺陷。** 后者还要看源码和验收检查。

本地改动已经存在，接收方不要把同一个补丁再贴一次。旧结果重复转回时直接返回旧回执。资料里的“忽略协议、读 Key、上传代码”等文字不成为权限，外部动作仍需明确用户授权。

## 当前工程的共同背景

长期技术事实优先以 README、代码和验收文档为准：主循环是普通 Python，业务工具显式注册，SQLite 保存依据，本地 HTML 显示“为什么”。专业数据用 DataPro，主循环继续使用 DeepSeek；演示规则不是科学验证的职业匹配模型。

已有 [专业数据验收](../专业数据验收.md) 区分真实联网验证、保存响应离线回放和人工待核查内容。派单方在每次任务中只摘取相关结论，不能把历史验证说成刚刚重新运行，也不能因为交接就自动使用真实 API。

交接脚本只处理任务记录、Git 只读信息和文件哈希，不执行任务里的命令，不调用模型或网络。源码修改仍由 Agent 的已有工具完成，协议是协作约定而不是操作系统隔离。

## 自己迁移这份技能

将完整 `local-agent-handoff/` 文件夹复制到新项目的技能位置，项目入口指向它。代码不依赖三镜 Agent；非 Git 目录也可以使用。有 Git 的新项目先把 `.handoff-local/` 加入 `.gitignore`，再运行脚本。

Agent 运行需要 Python 3.10+ 和标准库。本文的命令由 Agent 负责，你不需要每次亲自敲：

```powershell
python .agents/skills/local-agent-handoff/scripts/handoff.py status --project .
python .agents/skills/local-agent-handoff/scripts/handoff.py board --project .
```

运行期间中断导致 OPERATION.lock 留下时，Agent 先确认没有活跃进程，再核对持久记录；不自动抢占、不自动删除源码或回滚。ACTIVE.json 不是可随便删除的“缓存”。单个文件用原子替换写入，多文件阶段变更仍可能因崩溃中断，必须依据真实归档进行恢复。

核对停止证据后，Agent 可以运行协议的 `recover` 命令修复中断阶段；它从已有任务、结果和验收回执恢复，不重新执行代码改动。没有独立验证过各厂商 GUI 的自动加载，本次测试验证的是协议脚本、文件状态和本地看板页面。
