# 练习与答案

先读 [从教材到工程](先读这篇_从教材到工程.md)，再按兴趣选择练习。练习不要求调用真实模型，也不要求第一次就修改源码。

## 练习一：追踪 `append` 的结果

**先预测：** 教材示例中，`messages.append(message)` 执行后，列表是什么？`append` 表达式本身返回什么？

**运行：** 打开教材第 2 章的 `02_change_and_return.py`，运行后对照输出。

**答案：** 列表里多了一条字典，`append` 返回 `None`。主循环也是先把用户消息、助手工具调用和工具结果逐条追加到 `messages`，函数是否要返回状态对象是另外一件事。

## 练习二：找出工具调用与回执的配对

**先预测：** 如果助手的工具调用 ID 是 `call_abc`，工具结果应该使用哪个 ID？如果结果消息用 `call_xyz`，主循环能否知道它回答了哪次调用？

**运行：** 在离线演示中观察 `sanjing.agent` 的工具处理，并使用 `--trace` 查看脱敏调用 ID。

**答案：** 工具结果要原样带回 `call_abc`。ID 不匹配时，协议关联会断开；因此调用消息应完整保留，结果消息不能只靠工具名称猜配对关系。

## 练习三：故意提交一个不存在的证据 ID

**先预测：** 提交建议时引用 `evidence_fake`，但账本里没有这个 ID，会不会成为已验证建议？

**运行：** 先阅读 `tests/test_integration.py` 的 `test_partial_submission_repair_does_not_duplicate_success`：它会把一个提交请求的引用改为 `ev_fake`，再观察修正后的结果。可在工程目录运行 `python -m unittest discover -s tests -p test_integration.py -v`，不用先改文件。

**答案：** 这次错误提交会被拒绝，不创建对应的可发布建议；其余成功项可以先成为草稿。模拟模型修正引用后，本轮才发布完整建议，成功项不会重复。即使 ID 存在，也还要人工核对证据是否真的支持结论。

## 练习四：给页面注入一段 HTML

**先预测：** 如果某个资料片段是 `<script>alert(1)</script>`，静态页面会执行它，还是显示这些字符？

**运行：** 运行 `python -m unittest discover -s tests -p test_viewer.py -v`，查看 HTML 转义测试；在临时测试数据里替换一段资料文本后检查生成页面。

**答案：** HTML 源码里保存的是 `&lt;script&gt;` 等转义文本，浏览器显示 `<script>` 字符而不会执行它。`viewer._e` 负责转义，页面也没有业务 JavaScript。

## 练习五：修改一个规则版本

**先预测：** 把团队原型权重改动后仍使用旧版本号，查看旧建议时会发生什么问题？

**运行：** 找到 `sanjing/data/prototype_rules.json` 和 `tools._match_job`，阅读 `sanjing.store` 保存的规则版本字段。

**答案：** 新旧计算看起来像同一规则，旧账本无法说明当时的真实算法。改动规则时提升版本号，并让每条计算保存实际输入、贡献和版本；旧页面继续展示旧快照。

## 最后核对

- 工具调用失败是否能区分为“失败”，而不是“完成”？
- 页面展示的证据是否确实被当前建议引用？
- 假设、缺失信息和拦截事件是否被保留下来？
- 一条建议是否能从输入和规则版本解释其计算结果？
