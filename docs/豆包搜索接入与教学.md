# 豆包搜索怎样进入账本

你最初提出的“账本＋拦截”仍然是内核的骨架。这次只是增加了一种取得资料的方法。模型说“我要查官方招聘页”，程序检查请求后去搜索，给每条候选资料编号。模型读过需要的字段以后，才能把它放进正式建议。

Codex 的 `doubao-search` 技能教编码助手怎样访问豆包接口。产品 Agent 自己运行时没有 Codex 的技能加载器，所以我们参考技能的接口说明，写了一个普通 Python 请求函数，再把它放入产品的工具注册表。没有复制技能的旧凭据，也没有修改你的全局技能。

## 先跑一遍，再读代码

运行 `start.bat` 选项 7，或在工程目录运行：

```powershell
python -m sanjing.cli --web-demo --trace --once "核对合成岗位页面"
```

这不会读 Key，也不联网。终端应该依次显示 `search_web`、`get_record`、`submit_decision`。打开终端给出的 HTML，找“豆包网页搜索来源记录”和“豆包搜索使用统计”。候选资料和正式采用字段分别展示；点开执行事件，可以核对工具有没有成功。

真实模式运行 `python -m sanjing.cli`。可以输入：“搜索目标企业的官方校园招聘入口，只引用查到的链接与标题，列出具体职位尚需核实的事项。”费用由供应商记录；本地请求计数不能当作 AFP 扣费金额。搜索还需要套餐权限，凭证有效不等于每项服务都已开启。

## 跟踪一个字典

以下是数据形状示例，证据编号由你的实际运行生成。

1. `agent.run_turn()` 把用户问题加入消息列表，请模型选择工具。模型可能提出：

```python
{"query": "目标企业 官方校园招聘", "count": 1, "sites": ["example.org"]}
```

2. `tools.execute_tool(ctx, call)` 先看工具有没有注册，参数类型是否正确，权限是否允许。未知字段如 `url`、`command` 会被拒绝，函数不会执行。`sites` 是限定搜索结果的域名，不能是路径或请求地址。

3. `tools._search_web()` 检查搜索条件、查本轮缓存、检查四次查询上限，然后调用客户端。缓存包含查询、站点、时间范围和权威筛选；筛选不同就不是同一查询。失败的相同查询也会复用失败结果，避免反复收费尝试。

4. `doubao_search.search_web()` 从 DataPro 共用的工程外文件读 Key，固定请求官方搜索服务。地址与鉴权由程序决定，模型看不到 Key。服务返回标题、URL、摘要等字段；`normalize_response()` 保留字段来源，不把搜索摘要当网页全文，也不访问搜索结果中的 URL。

5. `tools._save_query_result()` 检查业务成功、类别、内容大小，再保存查询快照和独立候选证据。给模型的短索引不超过一千五百字符，例如：

```python
{"evidence_id": "ev_实际编号", "field_paths": ["/record/title", "/record/summary"]}
```

6. 模型调用 `get_record` 读取采用字段。索引只是“知道编号”，读取才表示“看过这个字段”。例如：

```python
{"record_type": "evidence", "record_id": "ev_实际编号", "field_path": "/record/summary"}
```

7. 模型调用 `submit_decision`，引用编号和字段路径。后端核对会话、读取记录、查询成功事件和字段存在性。网页证据必须来自 `search_web` 的成功事件，不能用一个失败调用冒充查询成功。事实字段由程序填入回复；模型分析单独标注。`viewer.write_snapshot()` 把这些关联画到“为什么”页面。

## 搜索和专业数据的分工

| 需要知道什么 | 优先工具 | 还要核对什么 |
|---|---|---|
| 企业登记主体、风险记录 | `query_professional_data` | 主体编号、查询覆盖范围、资料日期 |
| 行业与财务指标 | `query_professional_data` | 统计期、单位、地区与口径 |
| 官方招聘入口、政策页面 | `search_web` | 域名、发布日期、全文、职位有效性 |
| 学术资料的来源线索 | 专业查询，必要时补搜索 | 摘要是否支持分析、研究方法与适用范围 |

查到资料不等于验证事实。两次搜索命中同一网页也不等于两份独立证据。现在没有自动抓取全文的工具；使用摘要时要保留这个限制。搜索服务给出的权威标签也不代表每句话都正确。

## 参数与维护位置

`search_web` 允许 `query`、`count`、`sites`、`time_range`、`authority`。查询最多一百字符；结果数默认五条、最多十条；最多五个站点。时间范围为不限定、一天、一周、一月或一年；`authority=1` 请求权威来源筛选，默认零。不要把完整测评、简历或个人隐私塞入查询。

每轮搜索上限四次，专业数据仍是十六次，模型八次；共用三百秒全轮上限。单次六十秒，不自动重试；超时不能证明没有收费。响应超过一 MiB 不生成成功证据。两类外部来源共用现有存储格式，内部 `kind` 仍为 `professional_query` / `professional_record`；程序保存的 `category` 与 `source_type` 区分网页和专业数据，页面不会把网页标成专业数据库。

`run_turn(..., search_client=你的函数)` 可以替换搜索客户端。合成函数 `web_demo.demo_search_client(query, **options)` 是例子。主循环只传业务参数与剩余时间，不能把密钥交给这个工具。所有 CLI 离线模式都使用合成搜索客户端。

| 文件 | 看什么 |
|---|---|
| `sanjing/doubao_search.py` | 固定接口、请求参数、凭证隔离、结果映射 |
| `sanjing/tools.py` | 注册表、搜索计数、缓存、共用证据保存与引用检查 |
| `sanjing/agent.py` | 客户端注入、执行循环、进度与统计 |
| `sanjing/web_demo.py` | 三步离线模型与合成资料 |
| `tests/test_doubao_search.py` | 失败、拦截、引用及多轮快照检查 |

## 小练习与答案

先预测：把 `demo_search_client` 的合成 `summary` 改成另一句，正式回复会不会改变？运行后打开账本核对。答案：会，因为 `ask_web_demo` 读取并引用 `/record/summary`；它没有重新编写源字段。

再预测：只改 `title`，回复中的摘要会改变吗？答案：不会。候选标题会改变，正式采用的字段仍是摘要。这正是候选资料和实际依据的区别。

最后在 `ask_web_demo` 的首次调用参数里加 `command`。运行观察拦截事件，再删掉恢复。答案：搜索工具拒绝未知字段，不会执行网络客户端；模拟模型随后追问，不能提交未经核对的建议。

针对性测试：`python -m unittest discover -s tests -p test_doubao_search.py -v`。全量离线测试：`python -m unittest discover -s tests -q`。真实验收脚本 `python -m verification.search_live_check` 会产生用量，最多两次搜索和四次 Ark 请求，仅查公开入口；没有自动重试。

接口依据：[Agent Plan 团队搜索说明](https://docs.volcengine.com/docs/ark/agent-plan-enterprise-search?lang=zh)、[火山官方 MCP 搜索客户端源码](https://github.com/volcengine/mcp-server/blob/main/server/mcp_server_askecho_search_infinity/src/mcp_server_askecho_search_infinity/api/api_key_auth.py)。搜索接口为 `https://open.feedcoopapi.com/search_api/web_search`，使用 Bearer 鉴权；本工程始终从工程外文件读取。
