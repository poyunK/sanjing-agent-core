# 密钥扫描说明

发布 GitHub 时另运行 `python -m verification.release_check`：它显式扫描 DeepSeek、Ark、DataPro 当前凭证，覆盖工作文件、Git 暂存对象与全部可达历史 blob，并拦截暂存的运行数据与凭证文件。报告仅保存在被忽略的 `runtime/release_audit/`；任何扫描未完成都会返回失败。这仍是已知实际凭证的精确检查，不是对所有未知秘密的绝对保证。

本文解释交付前密钥扫描脚本 `verification/secret_check.py` 的三种结果，以及为什么“缺 Key”不能当作“已通过”。只引用工程里的真实函数。

## 脚本在做什么

`main()` 收集项目里的所有文件（跳过 `.git` 和 `.venv`），然后分别调用两个本地扫描函数。这一步不发送模型或专业数据请求：

1. `model.check_secret_leaks(paths)`（在 `sanjing/model.py`）：默认用旧 DeepSeek Key 精确匹配每个文件，返回 `verified`、`scanned_files` 和 `matching_files`。默认运行模型改为 Ark 不会悄悄改变这个扫描对象。
2. `datapro.scan_key_leaks(paths)`（在 `sanjing/datapro.py`）：用 DataPro Key 精确匹配每个文件，返回命中次数。

两个服务互相独立：一个失败不会阻止另一个运行。

当前 Ark 和 DataPro 默认共用同一个工程外文件，所以 DataPro 扫描也覆盖此文件中的实际 Ark Key。若以后分别配置不同文件，需另外显式运行 `model.check_secret_leaks(paths, provider="ark")`，并分别核对结果。

扫描脚本严格检查返回类型：`verified` 必须是 `True`，计数必须是非负整数，不能用 Python 的 `True`/`False` 冒充整数。DeepSeek 的命中数不能超过已扫描数，已扫描数不能超过传入文件数；DataPro 的 `None`、字符串和负数均不算成功。缺字段或异常属于未完成，不能用默认零掩盖。

## 三种扫描结果

脚本会把每个服务的结果标记为 `verified` 或 `error`，并给出 `summary_codes` 列表。

### 1. 已扫描，无命中（通过）

- `deepseek_status = "verified"`，`datapro_status = "verified"`。
- `deepseek.matching_files = 0`，`datapro_exact_key_occurrences = 0`。
- `summary_codes` 为空，脚本退出码为 0。

### 2. 发现命中（扫描完成，但未通过）

- 至少一个服务返回了非零命中数。
- `summary_codes` 包含 `SECRET_LEAK_FOUND`。
- 脚本退出码为 1。

注意：扫描仍然算“完成”，因为两个服务都成功跑完了；只是结果不安全，不能发布。

### 3. 尚未验证（不通过）

- 某个 Key 文件不存在、为空，或扫描过程中抛出了异常。
- 该服务状态为 `error`，无效计数为 `null`（未知）；DeepSeek 可能保留少量类型安全字段，不能据此当成完整扫描。
- `summary_codes` 包含 `DATAPRO_KEY_UNAVAILABLE`、`DATAPRO_SCAN_FAILED` 或 `DEEPSEEK_SCAN_FAILED`，并带有 `VERIFICATION_INCOMPLETE`。
- 脚本退出码为 1。

## 为什么缺 Key 不能当通过

如果把“缺 Key”当成“已查无泄漏”，攻击者只要删掉 Key 文件就能让扫描永远通过。因此脚本坚持：**未完成 ≠ 零泄漏**。任何未知状态都必须显式标出，并且阻止发布。

## 脱敏原则

- 报告和终端摘要只包含状态、计数和固定错误码。
- 不会输出 traceback、异常原文、Key 内容或命中正文。
- 扫描函数即使返回了 `reason`、请求头或其他附加字段，报告也只采用白名单字段，不原样复制它的整个字典。
- 即使扫描器抛出的异常里混入了敏感字符串，脚本也会把它映射成固定错误码，例如 `DataproError("KEY_UNAVAILABLE")` 只显示为 `DATAPRO_KEY_UNAVAILABLE`。

## 如何维护

- 新增扫描服务时，在 `run_secret_scan()` 里仿照现有两个 `try` 块：独立调用、独立记状态、异常映射为固定错误码。
- 修改报告字段时，保持 `deepseek`、`datapro_exact_key_occurrences`、`scan_completed`、`summary_codes` 这几个关键字段语义不变。
- 离线测试见 `tests/test_secret_check.py`：用 `unittest.mock.patch` 替换两个扫描函数即可模拟成功、缺 Key、异常和命中，不需要真实 Key 或网络。
- 测试同时把 `PROJECT_DIR` 替换为临时目录；报告只写临时位置，不覆盖或删除工程原有 `runtime` 报告。

```powershell
python -m unittest tests.test_secret_check -q
python -m verification.secret_check
```

前一条是合成测试，后一条检查本机实际 Key 的精确出现。只覆盖已配置的 Key，不证明所有其他未知凭证都不存在；当前脚本也不扫描 Git 历史对象。发布仓库时需要额外检查历史，不能只看这一份报告。
