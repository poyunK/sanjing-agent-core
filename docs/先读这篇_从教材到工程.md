# 先读这篇：从你学过的 Agent，走到三镜工程

这篇由主代理 GPT-6.1 Sol 结合工程源码与 `F:\#2642Agent` 的教材重新编写。你还没有读原来的工程文档，可以从这里开始。

你暂时不需要同时理解 SQLite、网页生成和线程。第一遍只追踪三件事：**模型返回什么，Python 执行什么，哪些东西被保存了。**

预计分两次读：第一次读到第 6 节，观察离线运行；第二次再读后面的小节，理解账本与维护。时间只是建议，不要求一次读完。

## 1. 先接上你已经学过的例子

原教材第 9 章的提问是“先算加法，再把结果乘以七”。模型先请求 `add`，Python 算出结果，再把结果发回模型；模型接着请求 `multiply`。

现在换成“比较用户研究和产品经理助理”，同一种循环变成：

```text
模型请求读取测评、检索岗位
Python 执行工具，返回资料和记录编号
模型请求匹配岗位
Python 按规则计算，返回分数、贡献和依据编号
模型请求提交建议
Python 检查引用，然后把保存的建议显示给用户
```

**循环的骨架仍然是请求、检查、执行、回传。** 工程新增的是执行前的检查、执行中的记账，以及发布建议前的检查。

第一遍不用把每个新函数都记住。先把 `run_turn()` 理解为原教材 `run_agent()` 的工程版本即可。

## 2. “一轮用户对话”与“一次模型请求”是什么关系？

你输入一句话，程序可能请求模型多次。工程把从你输入到程序结束这一段叫作一个 `turn`，即一轮用户对话。

一个典型的离线推荐回合是：

| 模型请求 | 模型提出的调用 | Python 接下来做什么 |
|---|---|---|
| 第一次 | `get_assessment`、`search_jobs` | 读取合成测评，找到两个演示岗位 |
| 第二次 | 两次 `match_job` | 分别计算两个岗位 |
| 第三次 | 两次 `submit_recommendation` | 检查并保存两条建议 |

这是一轮用户对话、三次模拟模型请求、六次工具调用。真实模型可以选择不同的调用顺序，因此不要把三次当成所有任务的固定次数。

源码里 `for step in range(MAX_STEPS)` 限制的是模型请求次数，当前上限为八次；里面的 `for call in calls` 遍历的是这次返回的工具调用。

**先预测：** 一次返回两个工具调用，是否马上消耗两次模型请求次数？

**答案：** 不会。两次工具执行都来自同一次模型响应。等 Python 把结果回传、再次请求模型时，才消耗下一次请求次数。

## 4. 一条工具请求到底长什么样？

下面是缩短后的结构示意，用于观察类型；`call_demo` 是教学编号，不是你实际运行得到的编号：

```python
message = {
    "role": "assistant",
    "content": "正在请求工具。",
    "tool_calls": [
        {
            "id": "call_demo",
            "type": "function",
            "function": {
                "name": "search_jobs",
                "arguments": '{"query": "用户研究", "limit": 1}',
            },
        }
    ],
}
```

逐层取值，不要一下跳到最里面：

```python
calls = message["tool_calls"]          # 列表：本次所有工具请求
call = calls[0]                        # 字典：第一个工具请求
function = call["function"]            # 字典：工具名称和参数文本
name = function["name"]               # 字符串：search_jobs
raw_arguments = function["arguments"] # 字符串：JSON文本
```

`raw_arguments` 看起来像字典，但它现在是**字符串**。转换后才能按字段取值：

```python
import json

arguments = json.loads(raw_arguments)
query = arguments["query"]
```

这段只说明 JSON 转换。真正工程中的 `safety.parse_arguments()` 还会检查大小、嵌套和重复字段；后面的 `validate_schema()` 检查这个工具允许哪些参数。

先看懂这些值怎么取，再去读 `tools.execute_tool(ctx, call)`，会容易很多。

## 5. `messages`、`ctx` 和账本，各自装什么？

它们都和“上下文”有关，但用途不同。

| 名称 | 放什么 | 谁使用 |
|---|---|---|
| `messages` | 发给模型的规则、对话与本轮工具结果 | 模型请求函数 |
| `ctx` | 当前会话 ID、轮次 ID、数据库位置、本轮允许引用的依据 ID | 本地 Python 工具 |
| SQLite 账本 | 用户原话、执行事件、证据、计算与建议 | 存储层、查询工具和查看页 |

**`ctx` 不是直接发给模型的消息。** 例如数据库路径只用于本地函数定位数据库，模型不会因此获得一个可以任意访问文件的工具。

`ctx["allowed_evidence_ids"]` 是一个集合 `set`。第一遍可以把它理解成“本轮允许引用的编号名单”：工具取得一条依据，就把编号加入名单；提交建议时，程序检查模型有没有引用名单之外的记录。

账本是持久化记录，关掉程序后仍存在。`messages` 是为这次执行准备的工作包；两者不需要长得完全一样。

## 6. 最关键的几行：调用、返回、追加

打开 [agent.py](../sanjing/agent.py)，在 `run_turn()` 中找到这段源码：

```python
reply = client(messages, tool_definitions())
```

`client` 在这里是**一个函数**。真实模式使用 `model.ask_llm`，离线模式传入 `offline.ask_offline`。因此主循环不需要为离线模式另外复制一份。

注意 `model.ask_llm` 与 `model.ask_llm(...)` 的区别：前者把函数交给另一个变量，后者立即调用这个函数。

`reply` 是请求函数返回的字典，工程从里面拿模型消息：

```python
message = reply["message"]
calls = message.get("tool_calls")
```

`.get("tool_calls")` 在没有这个字段时返回 `None`，不会直接产生 `KeyError`。判断是否存在调用后，工程保存完整助手消息：

```python
messages.append(message)
```

然后逐个执行：

```python
result = execute_tool(ctx, call)
```

**这行函数调用才会让本地 Python 进入工具执行流程。** 模型说“我调用了工具”，不等于本地已经执行；必须观察这行及其返回值。

工具结果的主要形状是：

```python
{
    "ok": True,
    "data": {"这里放业务结果": "例如岗位资料"},
    "error": None,
    "evidence_ids": ["这里放实际生成的依据编号"],
}
```

这是形状示意，具体字段要看相应工具。主循环把结果变成 JSON 文本，写入一条 `tool` 消息：

```python
messages.append({
    "role": "tool",
    "tool_call_id": call["id"],
    "content": json.dumps(redact(result), ensure_ascii=False),
})
```

`redact()` 会遮住常见密钥形式；`ensure_ascii=False` 让中文在 JSON 文本中保持可读。

再次提醒你教材中的重点：`append()` 修改原来的列表，返回值是 `None`。这里不能写成 `messages = messages.append(...)`。

**暂停检查：** 到这里，你能否指出哪一行调用模型、哪一行执行工具、哪一行把工具结果交给下一次请求？能指出，就可以先去观察终端，不必继续读所有辅助模块。

## 7. 三种编号不要混起来

| 编号 | 解决的问题 | 示例前缀 |
|---|---|---|
| `tool_call_id` | 这条工具结果回应哪一次调用？ | `call_...` |
| `evidence_id` | 建议引用的是哪一条依据？ | `ev_...` |
| `session_id` | 这些记录属于哪个本地会话？ | `session_...` |

调用编号通常来自模型响应，工具结果要原样配对；证据编号由 Python 存储层生成；会话编号把多轮记录归在一起。

例如两次调用都叫 `search_jobs`，它们的调用编号仍然不同。因此仅靠工具名字，无法判断某条结果对应哪次请求。

## 8. 为什么工具能自动记账？

自动记账由两处协作完成：

1. `execute_tool()` 统一记录请求了什么工具、允许还是拒绝、成功还是失败。
2. 业务函数取得值得保存的数据时，通过 `_save_evidence()` 保存证据及来源，并返回证据编号。

例如 `search_jobs` 保存候选岗位资料，`match_job` 保存规则与实际计算；`ask_user` 只返回固定追问，并不生成一条职业计算依据。

**不是每个工具都会自动生成证据。** 统一入口负责执行事件，业务函数负责具体证据。以后新增工具时，你仍要决定保存什么事实和来源，不能以为只注册一个名字就完成了溯源。

一次调用的 `call_id` 还会与执行事件关联；计算证据再关联到成功事件。提交建议时可以核对：这份计算是不是确实由成功的 `match_job` 产生。

## 9. 建议是怎样从账本变成回复的？

模型调用 `submit_recommendation` 时，会提供说明文字、计算编号、采用的依据编号以及限制。

程序检查这些编号在当前会话中存在、在本轮可引用；确认计算来自本轮成功的工具事件；要求计算使用的测评、岗位和规则都包含在引用中。检查失败时返回工具错误，模型还有机会在剩余请求次数内修正。

批次提交成功后，主循环读取保存的建议，再调用 `render_recommendations()` 生成回复。分数和贡献来自计算记录，模型说明会标注为模型生成。

这是与原教材的重要差别：教材可以直接显示模型最后的普通文字；这个原型要求建议先经过结构与引用检查。当前实现会拦截所有没有走发布工具的普通模型文字，包括普通聊天文本；这是第一版较严格的发布策略，不是所有 Agent 都必须如此。

模型要追问时使用 `ask_user`，程序从固定问题中选择并显示，状态为 `needs_input`。未来可以另行设计经过校验的自由追问。

查看页显示的是这些业务记录。它不会让模型在用户点击后重新补一套理由。

还要区分两件事：程序可以确认“引用确实存在、计算确实发生”；资料能否支持职业推论，仍需人工审查和规则验证。本版岗位权重只是演示假设。

## 10. 危险命令在哪里被拦住？

模型返回 `run_shell`，程序就查 `_TOOL_SPECS`。没有这个名字，会记录 `unknown_tool` 并返回失败，业务处理函数不会执行。

因此安全边界不是“模型答应不执行危险命令”，而是本地程序没有给它这个能力入口。现有工具也不接受任意路径、SQL 或代码文本。

离线模式中，你可以输入：

```text
演示危险命令拦截
```

模拟函数会故意返回未注册的 `run_shell` 请求，用来演示统一入口如何拒绝。这个名字没有对应的命令执行器。随后程序提出目标追问，整轮状态为 `needs_input`；被拒绝的执行事件仍能查到账本。

**一个工具被拒绝，不意味着整轮一定失败。** 工具错误可以回传给模型，它可以改用合法工具；无法修正或达到请求上限时，整轮才保持 `incomplete`。

## 11. 多轮恢复时，为什么没有把所有东西重新塞进模型？

本轮执行中，`messages` 保留完整工具调用与结果。回合结束后，数据库保存用户原话、正式回复和独立的业务记录；当前这串模型工具协议没有全部存成长期聊天历史。

下一轮，`context.build_messages()` 取预算内最近的完整对话回合，附带一些结构化条件和旧建议编号。旧依据按需通过 `get_record` 再读取。

因此，关掉程序再恢复同一个会话 ID，仍能查业务账本；但这不等于从一个被打断的模型请求中间继续执行。当前版本恢复的是会话与记录。

第一遍只需知道这个区别。SQLite 的 SQL 和上下文预算算法，可以在你想研究长期记忆时再看。

## 13. 三个自测，检查自己是否真的看懂

**题目一：** 模型返回“正在查询”，同时包含 `tool_calls`。能否因为有文字就当成最终回答？

**答案：** 不能。有调用时先校验和处理调用，文字不代表完成。

**题目二：** 工具保存了 `ev_x`，但它属于另一个会话。当前建议引用它，是否因为编号存在就应通过？

**答案：** 不能。记录必须属于当前会话，并满足本轮可引用条件。

**题目三：** 为什么替换 `client` 可以做离线测试，却不用重写 `run_turn()`？

**答案：** 两个函数接收相同的 `messages` 与工具描述，并返回相同形状的 `reply`。主循环只需要知道这个输入输出约定；真实 HTTP 和模拟响应分别在其他函数里实现。

如果第三题还不顺，可以只回到第 6 节，看“把函数交给变量”和“调用函数”的区别。学习不需要通过一次性看完所有文件来证明。
