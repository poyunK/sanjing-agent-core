# LAH/1.0 本地交接与看板验收

日期：2026-10-11。交付范围是本地通用 Skill、项目加载入口、文件交接脚本和持久任务看板；没有联网协调服务，也未自动向另一个 GUI 发消息。

## 已验证

- 原有工程与当时新增的二十三项交接测试：完整测试集 **117 项通过**。
- 随后补充中断领取测试并调整阶段检查：最新交接测试集 **24 项通过**，覆盖任意 Agent 标签、双向角色、只读与方案模式、真实字节哈希、现有未提交修改、越界与删除、重复领取、重复验收、伪造关联、结果后文件变化、待办修订、依赖与环路、取消、中断恢复、常见秘密路径和 HTML 转义。
- 官方 skill-creator 的 quick_validate：规范技能与 Claude 包装入口均通过。该开发校验器需要 PyYAML，仅安装到 Git 忽略的本地校验目录；运行交接脚本不需要第三方包。
- 本地看板：1440px 与 390px 两种尺寸均通过中文标签、五阶段列、文档宽度、无脚本和 CSP 检查；已查看实际渲染截图。横向列区在窄屏内部滚动。
- 当前真实看板为空，未把合成测试或格式样例伪装成用户的真实待办。测试均在临时项目里完成。

完整测试命令：`python -m unittest discover -s tests -q`；针对性交接测试：`python -m unittest discover -s tests -p test_handoff.py -q`。

浏览器验收脚本为 `verification/handoff_render_check.cjs`，截图和报告放 `.handoff-local/verification/`。它只用开发环境的 Playwright / Edge 读取本地页面，不是运行依赖。

## 验证边界

各厂商 GUI / Harness 的自动加载没有逐一启动验证。项目中已提供 AGENTS.md、CLAUDE.md、Codex 项目技能目录与 Claude 包装入口；任意其他 Harness 可以从任务文件开头读取同一协议。原生发现受具体客户端版本、配置和权限影响。

脚本验证任务关联、范围、部分凭证模式、哈希和阶段；不能证明人类授权真实、检查记录没有撒谎、代码语义正确或其他进程已经停止。占用是自愿协作规则，不是操作系统隔离。恢复命令需要 Agent 先核对停止证据。

没有真实模型/专业数据请求，没有新增 token 用量。交接不需要 Key。本次调用原有整工程精确密钥扫描时，工程外 DataPro Key 文件不可用（KEY_UNAVAILABLE），该整套扫描未完成；不能把此前的扫描结果冒充本次成功结果。新增文件和技能包只由本次源文件打包，未复制任何密钥文件、运行数据库或旧响应。

看板与任务记录放在 Git 忽略的 `.handoff-local/`，只存在这个本地工作副本。源码保留但看板目录被删会丢失任务历史；如需设备级备份或跨设备同步，必须另行安排。TASK、RESULT、RECEIPT 和规格修订记录保留；网页与 Markdown 看板可重建。

通信包基于同一个目录直接编辑：接收方验收现有改动，不重复应用补丁。跨 checkout、worktree、机器或云端会话不能直接复用同一项目身份。
